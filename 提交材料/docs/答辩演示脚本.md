# 5～8 分钟答辩演示脚本

## 演示准备

提前运行 `java -jar release/fat-lab.jar --self-test`，确认 PASS。演示时使用单独镜像：`java -jar release/fat-lab.jar --fat.disk=target/demo/disk.img`，浏览器访问本机 8080。不要把初始化指向需保留的数据。

## 演示顺序

1. **30 秒：说明磁盘。** 128 块 × 64 字节，FAT 在 0、1，根目录在 2；坏块 23、49；实际可分配 123 块。指出这是文件模拟磁盘。
2. **1 分钟：创建目录及文件。** `/doc` → `/doc/a.tx`。讲目录项是 8 字节，因此每块最多 8 项。创建文件后自动进入写模式，打开表出现记录。
3. **1 分钟：演示跨块。** 输入 64 个 ASCII 字符（下方提供），写入后观察链由一块增长为两块。强调额外一块保存 #，关闭后目录长度更新。
4. **1 分钟：演示读与追加。** 读 32 字节两次，观察读指针连续移动；关闭后追加 `中文`，观察字节长度增加 6。关闭并显示内容。
5. **1 分钟：演示限制。** 文件打开时尝试删除，提示拒绝；关闭后改只读，写入被拒绝；改回普通读写。
6. **1 分钟：解释缓冲。** 写一小段内容，展示 DIRTY；关闭后变 CLEAN。指出刷新状态不会强制写回，切换块才复用共享缓冲。
7. **30 秒：回收。** 关闭后删除文件，FAT 链全部归零；删除空目录后空闲数恢复 123。
8. **30 秒：验证与总结。** 展示测试报告，说明覆盖边界、空间不足、并发、损坏拒绝加载；明确没有断电事务恢复。

64 字节样例：

```text
012345678901234567890123456789012345678901234567890123456789ABCD
```

## 常见追问

**为什么 FAT 要占两块？** 128 项每项一字节，共 128 字节，每块 64 字节，需要两块。

**为什么 64 字节内容占两块？** 文件结束符 # 也占一字节，容量计算为 ceil((内容字节数+1)/64)。

**目录长度与打开表长度为何不同？** 磁盘目录项按指导书用盘块为单位；打开表用字节长度定位读写。重新打开沿链扫描 # 得到真实长度。

**如何追加？** 新写入从旧 # 所在位置覆盖，关闭时在新的末尾写 #。不支持随机中间修改。

**两个缓冲怎么支持五个文件？** 打开表只保留每文件的位置和状态，缓冲是共享的。更换块前刷回脏数据，避免串文件；所有操作串行化。

**为什么不能直接用真实文件目录或数据库？** 它们会替代本应实现的盘块分配、FAT 和目录项逻辑，失去本题模拟目标。

**如何避免死循环？** FAT 遍历维护 seen 集合，重复块立即报错；启动校验还维护跨文件占用集合，识别共享块和目录循环。

**空间不足会写一半吗？** 正常容量失败不会：预检查本次追加及结束符所需块数，再执行修改。底层 I/O 故障和强杀不具备事务保证。

**Java byte 的 255 怎么处理？** 用 Byte.toUnsignedInt 转为 0～255，不能直接用有符号 byte 当块号。

**并发是如何实现的？** Spring 可并发接收请求，核心使用同一实例锁串行化磁盘操作；测试中多个线程同时追加，结果保持一致。这是共享资源保护，不是进程调度模拟。

**为什么读中文可能显示不完整？** 接口按字节读，UTF-8 字符可能跨读取边界；始终返回原始 hex，完整显示文件仍可正确解码。

至少亲自运行一次完整流程，并能手算一个 63、64、128 字节文件的链长度。按真实参与情况填写报告分工和个人体会；不要声称实现了源码没有的断电恢复或并行磁盘访问。
